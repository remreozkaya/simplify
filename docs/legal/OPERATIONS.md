## Request handling runbook

- Register receipt time, reference and scope in a restricted case log. Assign an owner and 30-day deadline; respond sooner where possible. Keep only necessary identifying details.
- Match registered email and verified account identity. Use proportionate additional verification where justified. Never ask for the account password by email or return records to an unverified recipient. Written/formal requests require the fields described on the public Requests page under the applicable communiqué.
- Search Auth user/profile, provider audit/security and SMTP/hosting logs, prior correspondence and processor-held records. Local transcript/schedules are not available to staff; explain local export/clear and other-browser limitations. Do not ask users to upload a transcript solely to fulfill a deletion request.
- Provide accurate information about sources, purpose, recipients, overseas access and approved periods. Profile correction is available in the authenticated Profile UI; broader correction requests need processor coordination.
- Account export uses a fresh `auth.getUser()` verification and an explicit field allowlist; no client-supplied user ID, arbitrary metadata, password hash, tokens or cookies are returned. It is a useful account/profile download, not a full log-access response or a promise of universal portability.
- Automatic deletion verifies the session and confirmed email, then verifies the current password and matching account ID. It uses Supabase admin hard-delete for that ID only. There are no application table/upload deletes because none exist in this repository. Success is returned only after the admin API succeeds; local clearing follows only success. A provider failure must not be recorded as a completed deletion.
- Supabase access JWTs can remain cryptographically valid until expiry after account deletion. Protected personal pages and export/delete require `getUser()`; current public-catalog API authentication uses `getClaims()`. Do not promise instant revocation of every cached token. Test session behavior in the provider configuration and minimize lifetime appropriately.
- Examine every lawful retention exception, restrict any retained records, document grounds/expiry and notify relevant recipients of correction/deletion where required. Record disposal operations as required by the deletion regulation. Backups require provider-specific expiry/restore controls; restoring a backup must not reactivate deleted accounts without reapplying disposal decisions. Do not promise instantaneous deletion from backups.
- Send a reasoned written/electronic response and retain proof of notification date. Rejection/partial satisfaction must explain grounds and complaint routes. Case handling is generally free; charge only if a lawful Board tariff applies. Deadline: within 30 days. Complaint periods: 30 days from learning response and always within 60 days of controller application; explain no-response handling accurately.

## Incident response

Contain unauthorized access, revoke compromised secrets/sessions as appropriate, preserve minimal evidence, identify affected persons/data and contact processors. Assess Article 12(5) reporting immediately: Board without delay and within 72 hours of awareness under 2019/10; affected persons as soon as reasonably possible after identification. Document delay reasons, remediation and notification records. Rehearse recovery and redaction without using real academic records in test logs.
