# Simplify deployment privacy audit

Checked 2026-10-03. Scope: this workspace, not a deployed provider dashboard. No secrets or real user records were inspected or reproduced. `AGENTS.md`, README, package manifest/lockfile, App Router, Next.js 16.3.3 bundled route/action guides, auth, profile validation, all storage/fetch sites, OBS importers, snapshots and deployment files were examined. No application SQL schema, Supabase migration, database tables, object-storage integration, deployment manifest or CI configuration was found. `.env.local` values were not printed. Its presence is not proof of deployment contracts or region. The default Git shim required Xcode license acceptance; the installed Command Line Tools Git binary successfully provided status/diff. No git mutation was attempted.

## Verified service and data flow

- `src/components/profile/ProfilePage.tsx`, `src/lib/profile/types.ts`, profile actions: academic profiles, main major, double majors and minors. Metadata resides in the authenticated Supabase Auth user; no separate application table.
- `src/components/curriculum/GraduationCalculator.tsx`, `src/lib/curriculum/`: cumulative transcript import, program-specific graduation audit/GPA and prerequisite eligibility. Input is pasted text parsed locally, not document/file upload. Raw input is component state; parsed courses are persisted locally.
- `src/components/semester-planner/SmartSemesterPlanner.tsx`, `src/lib/semester-planner/`: course recommendations across active enrollments, bounded search and limitations.
- `src/components/calendar/ScheduleGeneratorPanel.tsx`, `src/lib/schedule/`: schedule generation and CRN/day/time preferences. `WeeklyCalendar.tsx` and `exportJpeg.ts`: saved named schedules and local JPEG export.
- Browser requests go to same-origin ITU API routes with branch, program, faculty and plan identifiers. Server-side OBS fetches carry those selectors and the server's network address, not users' transcripts/passwords. Plan selection can reveal academic interests in host logs even though transcripts stay local.
- Email/password auth, confirmation, recovery and profile changes use server-side Supabase clients. Cookies contain auth tokens/PKCE flow data. Profile includes name, surname, optional birthdate/nickname, program identities and update time. Supabase also has account ID/email, timestamps, identities, password hash and provider-managed session/security information; exact provider audit log fields are unresolved.
- No analytics, tracking pixels, advertising SDK, external iframe/embed, commercial messaging, payments or support-submission form was found in application code/dependencies. No sessionStorage or IndexedDB use found. `next/font/google` downloads Geist at build time and serves fonts locally; it does not intentionally make visitors request Google Fonts. The deployed CDN can introduce behavior not represented here.

## Browser storage inventory and assessment

Exact keys are centralized in `src/lib/legal/browserStorage.ts`; the bilingual policy lists every entry. Supabase SDK code was inspected (`@supabase/ssr/src/utils/constants.ts`, `cookies.ts`). Cookies are first-party on the Simplify origin, operated with Supabase SSR. All auth writes now enforce HttpOnly, SameSite=Lax and Secure in production, and server actions preserve the existing Remember me preference.

| Identifier | Function | Lifetime actually encoded |
|---|---|---|
| `sb-<project-ref>-auth-token[.n]` | Access/refresh session, chunks possible | SSR SDK default 400 days, renewed on writes; session cookie when Remember me is off. Token expiry differs from cookie expiry |
| `sb-<project-ref>-auth-token-code-verifier`, `...-flow-<id>-code-verifier`, `...-flows-code-verifier[.n]` | PKCE verifier / pending flows, depending on flow | Cleared on consumption; default upper cookie lifetime 400 days or session persistence setting; flow expiry is separate |
| `simplify-remember` | Requested login persistence | 365 days for remembered login, otherwise session |
| `simplify-password-recovery` | Restrict password reset to recovery session | 15 minutes |
| `simplify-verification-resend` | Verification resend throttling | 30 seconds |
| `simplify-weekly-programs` | Named schedules | localStorage, no expiry |
| `simplify-schedule-generator-session` | Generator session/preferences | localStorage, no expiry |
| `simplify-transcript-v1` | Shared parsed transcript | localStorage, no expiry |
| `simplify-curriculum-progress-v1` | Per-plan academic progress | localStorage, no expiry |
| `simplify-saved-curriculum-v1` | Last program/curriculum selection | localStorage, no expiry |
| `simplify-language` | Explicit language choice | localStorage, no expiry |
| `simplify-theme` | Explicit theme choice | localStorage, no expiry |

Authentication/recovery/throttle are necessary for the requested secure service. Durable academic storage supports requested saved planning, not tracking. Language/theme persist an explicit choice, not a behavioral profile; the cookie guide discusses user-selected personalization separately. Persistence length still needs proportionality review. No optional analytics category or fictitious consent evidence has been introduced. A future optional integration must remain disabled until purpose-specific consent blocking, retention, withdrawal and transfer assessments are implemented. Silent browsing is not consent.

**Shared-browser limitation:** keys are not account-scoped and survive logout. No new cross-account data migration was attempted. Collection notices warn before entry and public/Profile controls clear and export these keys. Account deletion clears only the current browser after server success; other browsers must be cleared separately. Owner should evaluate account isolation for shared-device use before launch.
